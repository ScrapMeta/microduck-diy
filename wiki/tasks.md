## 通用约定

> **本节按通用方式写，可整段搬到其他工程的台账** —— 状态 · 规则 · 数量口径都不需要改。

**状态（4 个 · 标准看板）** —— `待办` · `执行` · `阻塞` · `完成`（`To Do` / `In Progress` / `Blocked` / `Done`）；**本页四张表逐一对应**。

- `待办` —— 可以动手，还没开始
- `执行` —— 正在做（WIP）
- `阻塞` —— 开了但推不动；**为什么推不动，写在行里的「阻塞原因」**
- `完成` —— 终态。**完成和关闭都落这**，靠行内「结果说明」区分：
  - 真做完 → **完成**：结论 ＋ 落点
  - 不做 / 不值得追 → **关闭**：不采用 / 被谁吸收（**理由必须写清**）
  - 关闭不是淡出 —— 还可能要做的留在 `阻塞`，不往这儿搬

**编号** —— `T-01` 起两位定宽（满 99 续 `T-100`）：**一经分配不再变动、不复用**，编号**随行**走状态。
用途：`log.md`、页间引用和对话都能指认同一条任务，不用抄任务名。
编号自 2026-09-19 启用；此前的条目**无编号**（靠 `出处` 追溯），**不回溯补号**。

**规则（4 条）**

1. **只追加、不改旧行** —— 要改就追加新行或改状态；原文永远在 git 历史里。
2. **开 ＋ 关同页** —— 完成 / 关闭**就地**在本页改状态，不另建页、不搬行。
3. **完成 ≠ 关闭** —— 完成要过本行写明的**验收**；关闭是判定不做。**同一张表里，靠「结果说明」区分**。
4. **准入** —— 验收必须**可勾掉**：无界验收（开口、永远勾不掉）先收窄才准立项。

**数量 —— 不设上限**：想开就开，**不因条数多而拒绝**；台账太长**由人工收拢**（`push main` → `完成` 行一批归档 Issue → 从本页删掉该批行），agent 不替人砍任务。

**分工** —— 台账**全员可开 / 更新 / 关**；**push 与 Issue 归档只有 pm**。
