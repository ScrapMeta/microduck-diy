# XL330 vs Kpower RD05T — 能否平替？

> **状态：评估中（2026-09-18）· 无实物 · 结论可被 §5 第 2 步推翻**
>
> **结论：**
> 1. **铭牌几乎逐项等同 XL330-M288-T**——疑似同源电机 + 同档齿轮箱，规格书是对着 XL330 数据手册写的。
> 2. **接口：确认兼容**（连接器、引脚、电平、UART 帧格式）。
> 3. **「协议一样」未被证明**——规格书只给物理层，**没给寄存器地址表**。这是第一阻塞。
> 4. **即使协议相同，也不满足「替掉原厂训练结果」**——动力学未辨识，且**能否辨识也不确定**（§4.5）。

来源：原始 ingest [`raw/articles/kpower-rd05t-spec-2026-09-18.md`](../raw/articles/kpower-rd05t-spec-2026-09-18.md)；
XL330 侧权威值取自 [eManual XL330-M288](https://emanual.robotis.com/docs/en/dxl/x/xl330-m288/)（2026-09-18 取）。

**派生量**（本项目关心的真参数）：

| 量 | XL330 | RD05T | 差 |
|----|-------|-------|-----|
| 扭矩常数 Kt = τ/I | 0.345 N·m/A @6 V | 0.588/1.740 = **0.338** | **−2 %** |

| 线长 | — | 180±10 mm | — |

**用户判断「接口一样」成立**：机械能插、电平能通、UART 帧一致。

## 3. 「协议一样」未被证明 ⚠️

**协议 ≠ 波特率 + 8N1。协议 = 寄存器地址表。** 规格书给了前者，没给后者。

| 疑点 | 说明 |
|------|------|
| 未写 DYNAMIXEL Protocol 2.0 | 只写「TTL (Half Duplex)」。Kpower 官网自家产品线分类是 `PWM / UART-TTL / RS-485 / CAN-bus` |
| ID 范围 **0~253** | XL330 是「**253 ID (0~252)**」。差一个号——DXL 2.0 中 253 为保留（1.0 的广播号） |
| 「Control System」三选一 | PWM / RS-485 / CAN 同壳可选；末尾原文「**控制协议可定制**」→ 到手的可能是任意一版固件 |
| 无工作模式 / 无减速比 | 见 §1 缺项 |

**为何是硬阻塞**：`robotd` + `rustypot` 按固定地址表通信（`Goal Position(116)` · `Present Position(132)` ·
`Torque Enable(64)` · `Shutdown(63)` …）。地址对不上**连读位置都做不到**。
且总线**共挂 [[imu-to-dxl-v2]]（DXL 从机 ID 200）**——只有真 DXL 协议设备能共用。

## 4. 若协议真的一样，原厂训练结果会出什么问题

原厂策略依赖：MuJoCo 里用 **BAM 的 XL330-288-T 摩擦模型**训练，50 Hz，`obs 61 → act 14`；
部署时内部 PID 用 **XL330 出厂默认增益**（`robotd` 只写 `return_delay=0` · `baud=3` · `pwm_slope=255` · `shutdown=52`，**不写增益**）。
即策略学到的是**含执行器传递函数的闭环**。

### 4.1 直接打掉 sim2real（最严重）

| 差异 | 后果 |
|------|------|
| **过载离合**（RD05T 独有） | XL330 无此机构。离合 = **串联弹性 + 滑移**元件 → 降低等效关节刚度。它的影响**不只在过载时**，平时也贡献柔度，而**策略里没有这个元件** |
| **BAM 摩擦模型失效** | BAM 拟合的是 XL330 的齿轮材质/润滑/预紧与库仑+黏滞+负载相关摩擦；POM 齿 + 不同润滑 = 另一条曲线。**摩擦是足式 sim2real 的头号杀手** |
| **齿轮虚位未标** | 回差使「位置读数」与「实际输出角」之间出现**随负载反向变号**的偏置 → 污染本体感知（尤其脚掌/踝） |
| **减速比未标** | 折算到关节的转子惯量 ∝ N²；比值不同则惯量与摩擦的负载相关性全变 |

### 4.2 闭环响应错位

| 差异 | 后果 |
|------|------|
| **内部 PID 增益未知、未必可写** | 同一位置指令产出**另一条关节轨迹**；策略的稳定裕度就建立在这条轨迹上 |
| **工作模式缺失** | 若只有「位置+速度」，失去 Current-based Position 的柔顺/力控能力 |
| **延迟** | `Return Delay Time` 能否设 0 未知、内部环周期未知。50 Hz 策略对毫秒级延迟敏感 |
| **空载电流 280 mA** | XL330 未公布 → **无法比对**；若偏高则摩擦更大（不利） |

### 4.3 保护逻辑误触发（最可能「直接跑不起来」）

| 差异 | 后果 |
|------|------|
| **过压阈值未知、未必可设** | XL330 的 `Max Voltage Limit(32)` 默认 **70 = 7.0 V** 且**可设**。本项目母线跑 **6.0–6.5 V**（官方电池 6.6–8.2 V）。若 RD05T 过压阈值卡在标称 **6.0 V** 且不可调 → **6.5 V 持续过压**、torque off、红灯闪、机器人瘫 |
| **过流阈值未知** | 走路有 2–3× 额定电流的冲击尖峰。阈值低 + **锁存** → 走着走着一腿失力。XL330 用 `Shutdown(63)` 位表决定哪些故障锁（并已被 `robotd` 清掉 Input Voltage 位）；RD05T 阈值与恢复语义**全未知** |
| **额定扭矩 = 堵转 25 %** | 0.147 N·m 是**连续工作上限**；持续超了即热降额/过热保护（与 [[dynamixel-xl330]] 的台架母线定案相关） |

### 4.4 观测与标定失真

- 反馈缺 **Realtime tick** 与 **Trajectory**（XL330 有）→ 时间同步 / 轨迹模式不可用
- **回中差 / 定位精度未标** → 出厂零位与一致性无保证；安装角若不同，**必须重标 home offset**
- 速度反馈实现方式未知（差分/滤波各家不同）→ `obs` 里的速度项就是另一个数

### 4.5 同时失去诊断与再辨识能力

- **诊断**：`scripts/dxl_ping.py` 读的就是 DXL 地址（`Model Number(0)` 期望 **1200**）。对不上则
  [[dxl-bench-method]] 的整套基线口径失效 → **没有可比的台架数据**
- **再辨识**：[[bam-identification-bench]] 的电气前提明确要求「能读位置/速度/电压、**可写 P 增益寄存器**、
  堵转 ≥0.3 N·m」。RD05T 堵转 0.588 N·m ✓ 过关，但**若不暴露可写 P 增益 → BAM 做不了 → 本项目 sim2real 路线上直接出局**

## 5. 判定路径（第 2 步最便宜且决定性）

| # | 动作 | 通过判据 |
|---|------|----------|
| 1 | 向 Kpower 索取**协议/寄存器手册** | 逐地址对照 DXL 2.0 控制表，尤其 `Protocol Type(13)`、`Position P Gain(84)` **可写**、`Max Voltage Limit(32)` **可写** |
| 2 | **上台架实测**（现有 HAT 总线，几分钟）<br>`python3 scripts/dxl_ping.py info --port /dev/ttyS2 --baud 57600 --id 1` | `Model Number` 读回 **1200** = 自称 XL330 身份；读回别的或**无回包** = 寄存器不兼容。**不用猜** |
| 3 | 实测过压边界：母线 6.0 → 6.3 → 6.5 V | 何时报警/失力；阈值可否改 |
| 4 | 机械核对 | 花键齿数能否套 XL330 舵盘与现打印件；**副输出轴**是否与打印关节几何冲突 |

## 6. 分用途结论

| 用途 | 判定 |
|------|------|
| **替代原厂训练结果的整机执行器** | **不要**。须重跑 BAM 辨识（数天–数周）＋重训；且 §4.5 的不确定性可能让它**连辨识都做不了** |
| **台架 / 调试 / 教学备件** | **合适**（前提：第 2 步通过）。练 DXL 总线、ID/波特率、焊接治具时动力学不重要 |
| **消耗位 / 易损位** | 可评估，但**勿与 XL330 混挂在同一条受策略驱动的总线上** |

与既有归档结论一致（[[xl330-vs-feetech-servos]] · [[xl330-vs-unitree-s288]]）：
**铭牌接近 ≠ drop-in；换执行器必须重辨识或重训。**
