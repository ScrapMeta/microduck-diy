# XL330 vs Kpower RD05T — 能否平替？

> **状态：评估中（2026-09-18）· 无实物 · 结论可被 §5 第 2 步推翻**
>
> **结论：**
> 1. **铭牌几乎逐项等同 XL330-M288-T**——疑似同源电机 + 同档齿轮箱，规格书是对着 XL330 数据手册写的。
> 2. **接口：确认兼容**（连接器、引脚、电平、UART 帧格式）。
> 3. **「协议一样」未被证明**——规格书只给物理层，**没给寄存器地址表**。这是第一阻塞。
> 4. **即使协议相同，也不满足「替掉原厂训练结果」**——动力学未辨识，且**能否辨识也不确定**（§4.5）。
> 5. **一处风险已降级（2026-09-18）**：母线定案 **6.0 V**（非 6.5 V）→ **两侧运行点都在各自标称上限、不存在系统性过压**，§4.3 原头号「直接跑不起来」项随之降级为「余量」问题。

来源：原始 ingest [`raw/articles/kpower-rd05t-spec-2026-09-18.md`](../raw/articles/kpower-rd05t-spec-2026-09-18.md)；
XL330 侧权威值取自 [eManual XL330-M288](https://emanual.robotis.com/docs/en/dxl/x/xl330-m288/)（2026-09-18 取）。

| 量 | XL330 | RD05T | 差 |
|----|-------|-------|-----|
| 扭矩常数 Kt = τ/I | 0.345 N·m/A @6 V | 0.588/1.740 = **0.338** | **−2 %** |

## 3. 「协议一样」未被证明 ⚠️

**协议 ≠ 波特率 + 8N1。协议 = 寄存器地址表。** 规格书给了前者，没给后者。

### 3.1 「能上 DYNAMIXEL Wizard 并识别成 XL330」能证明什么（2026-09-18）

厂商称可直接上 Wizard 且识别成 XL330。**会发生——但这恰恰是最弱的证据。**

原因：Wizard 按 **`Model Number(0)` 做表查找**。克隆件只要回 **1200**，Wizard 就套上
XL330-M288-T 的寄存器表并如此显示。它证明的是**身份声明**，不是**寄存器语义相同**
——与 `scripts/servo_swap_compare.py` 里那个「非 1200 即拒绝」的守卫检的是**同一件事**。

Wizard 里真正有区分力的测法，按证明力分三档：

| 档 | 测法 | 证明 |
|----|------|------|
| 弱 | 读 `Model Number(0)`、逐个读寄存器 | 身份声明 + 物理层通 |
| 中 | **写** `Return Delay Time(9)=0` · `Baud Rate(8)=3` · `Shutdown(63)=52`，再读回 | 寄存器**可写** —— 即 `robotd` 的收养路径能否成立 |
| **强** | 写 `Position P Gain(84)` 到一个明显值，**再观察阶跃响应是否真的变硬/变软** | 寄存器**被固件使用** —— 即 BAM 辨识的前提 |

**只读不算证明。** 读得到 ≠ 有效：固件可以「把值存下来但不用」。

**⚠ Wizard 的陷阱（必须知道）**：Wizard 套用的是 **XL330 的寄存器表，含其合法范围与单位**。
克隆件若在某地址上实际含义/范围不同，Wizard **仍按 XL330 显示**，你**看不出差别**。
这正是本 wiki 已记录过的那类「合理但错误」的数（`model=45056`、
`max_voltage_limit=1792.0 V`——看着都像对的，其实整体错位）。
**工具本身会掩盖差异**，所以「Wizard 正常」不能当作通过。

### 3.2 Wizard 现在就能回答的两件事（不必等台架）

1. **`0x55` 帧异常是否复现** —— 见 `scripts/README.md` §「两个已踩过的坑」：
   本套件 XL330-CN 的状态帧多一个固定字节（`LEN = DATA + 4`），来源未定论。
   Wizard 是**独立实现**，能一锤定音判定它是固件怪癖还是我们的脚本问题。
2. 上表**中/强**两档的寄存器可写性。

### 3.3 其余疑点

| 疑点 | 说明 |
|------|------|
| 未写 DYNAMIXEL Protocol 2.0 | 只写「TTL (Half Duplex)」。Kpower 官网自家产品线分类是 `PWM / UART-TTL / RS-485 / CAN-bus` |
| ID 范围 **0~253** | XL330 是「**253 ID (0~252)**」。差一个号——DXL 2.0 中 253 为保留（1.0 的广播号） |
| 「Control System」三选一 | PWM / RS-485 / CAN 同壳可选；末尾原文「**控制协议可定制**」→ 到手的可能是任意一版固件 |
| 无工作模式 / 无减速比 | 见 §1 缺项 |

**为何是硬阻塞**：`robotd` + `rustypot` 按固定地址表通信（`Goal Position(116)` · `Present Position(132)` ·
`Torque Enable(64)` · `Shutdown(63)` …）。地址对不上**连读位置都做不到**。
且总线**共挂 [[imu-to-dxl-v2]]（DXL 从机 ID 200）**——只有真 DXL 协议设备能共用。

## 4. 若协议真的一样，原厂训练结果会出什么问题

原厂策略依赖：MuJoCo 里用 **BAM 的 XL330-288-T 摩擦模型**训练，50 Hz，`obs 61 → act 14`；
部署时内部 PID 用 **XL330 出厂默认增益**（`robotd` 只写 `return_delay=0` · `baud=3` · `pwm_slope=255` · `shutdown=52`，**不写增益**）。
即策略学到的是**含执行器传递函数的闭环**。

### 4.1 直接打掉 sim2real（最严重）

| 差异 | 后果 |
|------|------|
| **过载离合**（RD05T 独有） | XL330 无此机构。离合 = **串联弹性 + 滑移**元件 → 降低等效关节刚度。它的影响**不只在过载时**，平时也贡献柔度，而**策略里没有这个元件** |
| **BAM 摩擦模型失效** | BAM 拟合的是 XL330 的齿轮材质/润滑/预紧与库仑+黏滞+负载相关摩擦；POM 齿 + 不同润滑 = 另一条曲线。**摩擦是足式 sim2real 的头号杀手** |
| **齿轮虚位未标** | 回差使「位置读数」与「实际输出角」之间出现**随负载反向变号**的偏置 → 污染本体感知（尤其脚掌/踝） |
| **减速比未标** | 折算到关节的转子惯量 ∝ N²；比值不同则惯量与摩擦的负载相关性全变 |

### 4.2 闭环响应错位

| 差异 | 后果 |
|------|------|
| **内部 PID 增益未知、未必可写** | 同一位置指令产出**另一条关节轨迹**；策略的稳定裕度就建立在这条轨迹上 |
| **增益会被 `Operating Mode` 重置** | XL330 手册明确：切换 `Operating Mode(11)` 会**重置** `Position PID(80, 82, 84)` 与 `Velocity PI(76, 78)`。→ 写入顺序**必须先设模式、再设增益**。若克隆件不遵循此规则（或不重置、或在不同模式下重置不同项），**同一条命令序列会得到不同的最终增益**——而且读回值可能都"对" |
| **工作模式缺失** | 若只有「位置+速度」，失去 Current-based Position 的柔顺/力控能力 |
| **延迟** | `Return Delay Time` 能否设 0 未知、内部环周期未知。50 Hz 策略对毫秒级延迟敏感 |
| **空载电流 280 mA** | XL330 未公布 → **无法比对**；若偏高则摩擦更大（不利） |

### 4.3 保护逻辑误触发（最可能「直接跑不起来」）

| 差异 | 后果 |
|------|------|
| **过压阈值未知、未必可设**（**风险已降级 · 2026-09-18**） | XL330 的 `Max Voltage Limit(32)` 默认 **70 = 7.0 V**，可设但**只能调低**。**本项目母线定案 6.0 V**（= 两侧标称上限，非超出）→ 原先「6.5 V 持续过压」的场景**不再存在**。**残余风险变成「余量」**：若 RD05T 跳闸点恰卡在 6.0 V，则降压模块超调 / 多台同时制动回灌即可能误跳 → 仍须问余量，但**已不是「直接跑不起来」的头号项** |
| **过流阈值未知** | 走路有 2–3× 额定电流的冲击尖峰。阈值低 + **锁存** → 走着走着一腿失力。XL330 用 `Shutdown(63)` 位表决定哪些故障锁（并已被 `robotd` 清掉 Input Voltage 位）；RD05T 阈值与恢复语义**全未知** |
| **额定扭矩 = 堵转 25 %** | 0.147 N·m 是**连续工作上限**；持续超了即热降额/过热保护（与 [[dynamixel-xl330]] 的台架母线定案相关） |

### 4.4 观测与标定失真

- 反馈缺 **Realtime tick** 与 **Trajectory**（XL330 有）→ 时间同步 / 轨迹模式不可用
- **回中差 / 定位精度未标** → 出厂零位与一致性无保证；安装角若不同，**必须重标 home offset**
- 速度反馈实现方式未知（差分/滤波各家不同）→ `obs` 里的速度项就是另一个数

### 4.5 同时失去诊断与再辨识能力

- **诊断**：`scripts/dxl_ping.py` 读的就是 DXL 地址（`Model Number(0)` 期望 **1200**）。对不上则
  [[dxl-bench-method]] 的整套基线口径失效 → **没有可比的台架数据**
- **再辨识**：[[bam-identification-bench]] 的电气前提要求「能读位置/速度/电压、**可写 P 增益寄存器**、
  堵转 ≥0.3 N·m」。RD05T 堵转 0.588 N·m ✓ 过关，但**若不暴露可写 P 增益 → BAM 做不了 → 本项目 sim2real 路线上直接出局**
  - **该前提不是社区笔记的转述，而是 BAM 源码本身的行为**（2026-09-18 核对）：`bam/dynamixel/record.py:65`
    在辨识 setup 循环里**每轮**调用 `write_position_p_gain(ID, args.kp)`；本项目
    `refs/microduck_rl/scripts/testbench_sim2real.py:317` 同样先写、`:322` 再读回校验。
    → **P 增益不可写 = 辨识工具直接跑不起来**，这不是我们的额外要求

## 5. 判定路径（第 2 步最便宜且决定性）

| # | 动作 | 通过判据 |
|---|------|----------|
| 1 | 向 Kpower 索取**协议/寄存器手册**<br>（询问函已备：[[rd05t-vendor-inquiry-2026-09-18]]）| 逐地址对照 DXL 2.0 控制表，尤其 `Protocol Type(13)`、`Position P Gain(84)` **可写**、`Max Voltage Limit(32)` **可写** |
| 2 | **上台架实测**（现有 HAT 总线，几分钟）<br>`python3 scripts/dxl_ping.py info --port /dev/ttyS2 --baud 57600 --id 1` | `Model Number` 读回 **1200** = 自称 XL330 身份；读回别的或**无回包** = 寄存器不兼容。**不用猜** |
| 2b | **Wizard 写-读-行为**（不必等台架，见 §3.1）<br>写 `Return Delay Time=0` · `Baud Rate=3` · `Shutdown=52` 读回；再写 `Position P Gain` 并**看阶跃是否真变** | ①时钟可写 ②**P 增益可写且被固件使用** ← BAM 路径的电气闸门。<br>顺带定论 `0x55` 帧异常 |
| 3 | 实测过压边界：母线 6.0 → 6.3 → 6.5 V（**6.0 是运行点**，上探只为量**余量**）| 跳闸点相对 **6.0 V** 留多少余量；阈值可否改；制动回灌是否误跳 |
| 4 | 机械核对 | 花键齿数能否套 XL330 舵盘与现打印件；**副输出轴**是否与打印关节几何冲突 |
| **5a** | **空载 A/B**（约 1 小时，**不需摆臂**）<br>`scripts/servo_swap_compare.py` | **`dead_steps`=0**、`hysteresis`/`dead_time` 在 **1.25×** 内 → 判定离合/虚位 |
| 5b | **负载 A/B**（需摆臂台，约 1 天）| 补上 `ramp_slow` 的**摩擦对比**；含 5a 全部指标 |
| 6 | 若 5b 通过且分型为「仅摩擦」→ **BAM 辨识** | 见 [[bam-identification-bench]] §「分阶测试」的决策表 |

**顺序原则**：**先便宜的、能出结论的**。2/2b 几分钟、5a 一小时，就能判掉「离合/虚位」这个
**辨识救不了**的风险；**别先投 BAM 辨识（数天–数周）**。

**第 2b 与第 5 步的分工**：2b 判「**通上话之后寄存器是否真的有效**」（语义）；
第 5 步判「**有效之后行为像不像**」（动力学），并把 §4.1 那个
「离合 = 串联弹性」的猜想从推断变成**可测量的数**。第 2b 是 5 的电气闸门：
`Position P Gain(84)` 不可写或不生效则 §4.5 的再辨识路径直接断掉，5b/6 都不必做。

**注意：这些都**不能**证明整机可替换。BAM 是**单台**辨识的，15 台之间的批次散布是
另一件事，且 1~2 台测不出。

## 6. 分用途结论

| 用途 | 判定 |
|------|------|
| **替代原厂训练结果的整机执行器** | **不要**。须重跑 BAM 辨识（数天–数周）＋重训；且 §4.5 的不确定性可能让它**连辨识都做不了** |
| **台架 / 调试 / 教学备件** | **合适**（前提：第 2 步通过）。练 DXL 总线、ID/波特率、焊接治具时动力学不重要 |
| **消耗位 / 易损位** | 可评估，但**勿与 XL330 混挂在同一条受策略驱动的总线上** |

与既有归档结论一致（[[xl330-vs-feetech-servos]] · [[xl330-vs-unitree-s288]]）：
**铭牌接近 ≠ drop-in；换执行器必须重辨识或重训。**
