# XL330 vs SIAR MD 系列（VKESMD）

> **状态：厂商文档已逐条核对（2026-09-21）· 无实物 · 厂商未给规格书**
>
> **结论：厂商「外形、参数、寄存器一摸一样」的三项声明，按它自己给的资料 —— 后两项对不上，且第二项是硬伤。**
>
> 1. **寄存器不成立。** 地址表与 XL330 **无一运动核心同址**（ID 5 vs 7 · 目标位置 42 vs 116 · 当前位置 56 vs 132 ·
>    模式 33 vs 11 · 扭矩开关 40 vs 64 · P 增益 21 vs 84 …），**连「型号」都没有**：XL330 靠
>    `Model Number(0) = 1200` 自报身份，MD 的地址 0 是固件主版本号（出厂 3）。它反而**与飞特 SCS/STS/SMS 同构**（§4）。
> 2. **帧格式不是 XL330 的 Protocol 2.0。** `FF FF` + `~和` 校验 = **DXL 1.0 / 飞特 SCS 血统**；
>    XL330 出厂是 2.0（`FF FF FD 00` + CRC16）。
> 3. **「参数」这批资料证明不了。** 三份全是寄存器 / 协议 / 上位机文档，**尺寸·重量·扭矩·转速·额定电压全缺**
>    （内存表模板里那两栏是空的）。能对上的只有 **4096 step/圈（0.0879°）** 这一格。
> 4. 文档**内部有 6 处自相矛盾**（[[vkesmd-md-series-docs-2026-09-21]] §5）→ 一个模板套多型号 / 多固件代，
>    **不能按「一个型号」判断**。
> 5. 定性：这是**换了协议的执行器**（与 [[feetech-hd-1910]] 同类），**不是 XL330 的克隆**。
>    要上整机得走 [[feetech-scs-bus]] §6「加第 4 个 `RobotIo` 后端」那条路 —— **不是** [[xl330-vs-kpower-rd05t]]
>    那种「可能只差动力学」的局面。

## 1. 来源与身份

| 项 | 值 |
|----|-----|
| 厂商声明（用户转述） | 外形 · 参数 · 寄存器「跟原厂 XL330 一摸一样」 |
| 资料 | 3 份（内存表 xlsx · 485/TTL 协议 docx · VKESMD 上位机手册 docx）+ 1 页 SDK 宣传；原件存档 `raw/assets/vkesmd/` |
| 自述身份 | 品牌 **SIAR**（SDK 页）· 系列 **MD 系列** · 上位机 **VKESMD Debug** · 固件 `SMServo2.40-STM32-485(190225).bin` |
| **具体型号** | **未知** —— 三份文档从未给出型号，也没有规格书 |
| 获取渠道 | 厂商飞书 wiki（`coremotion`），**需登录**；本轮由 Human 本地下载后交付 |

> 与 [[xl330-vs-kpower-rd05t]] 的 RD05T 是不是同一款，资料里没有交集（那边的厂名是「东莞市伟创动力 / Kpower」）
> —— **待 Human 确认**，在确认前**不要把两批结论互相套用**。

## 2. 帧格式对照

| | **XL330**（Protocol 2.0，出厂） | **SIAR MD** |
|---|---|---|
| 帧头 | `FF FF FD 00`（**4 字节**）| `FF FF`（**2 字节**）|
| 长度字段 | 指令 `LEN = N+3`；状态含 CRC（本项目实测 CN 件为 `LEN = 数据+4`）| 指令 / 状态**都是** `LEN = N+2`（状态字节另计）|
| 校验 | **CRC16**（多项式 0x8005，低字节在前）| **`~(ID + LEN + INSTR + ΣPARAM) & 0xFF`** |
| ID | 0–252（253 保留）| 0–253（**254 广播**）|
| 指令集 | PING 1 · READ 2 · WRITE 3 · REG_WRITE 4 · ACTION 5 · FACTORY_RESET 6 · **REBOOT 8** · SYNC_READ 0x82 · SYNC_WRITE 0x83 | PING 1 · READ 2 · WRITE 3 · REGWRITE 4 · ACTION 5 · RESET 6（「把控制表复位为出厂值」）· **圈数清除 0x0A** · SYNCREAD 0x82 · SYNCWRITE 0x83 |
| 字节序 | 小端 | 小端（`02` §2.1.1 原文「不同型号舵机字节顺序不一样」）|

**指令号看着像，是因为飞特就是照 DXL 1.0 抄的**（[[feetech-scs-bus]] §1 已定论：帧格式与 DXL 1.0 逐字相同）。
**「一样的协议」这句话在指令号层面成立，在帧头与校验层面不成立** —— 而这两层任一不符，`robotd` 就收不到回包。

> ⚠️ XL330 **确实能把 `Protocol Type(13)` 切成 1.0**（默认 2）。切过去后**帧格式会与 MD 同构**，
> 但地址表仍是 Robotis 的 1.0 表（≠ 本页 2.0 表，也 ≠ MD 表）。**eManual 该页只列 2.0 控制表，1.0 表本轮未核**。
> 即便 1.0 表能对上，**`robotd` / rustypot 走的是 2.0**，整机结论不变。

## 3. 地址对照（只列运动核心）

| 功能 | **XL330**（2.0） | **MD 系列** | |
|---|---|---|---|
| **型号** | **0**（只读，固定 **1200**）| **无**（0 = 固件主版本号，出厂 3）| **没有可比对象** |
| ID | 7 | 5 | 异 |
| 波特率 | 8（`1`=57 600 · `3`=1 M）| 6（`0`=1 M · `6`=57 600）| 异（表也不同）|
| 回包延时 | 9（出厂 250，`robotd` **必须清 0**）| **无**（7 是副 ID）| 异 |
| Protocol Type | 13（默认 2）| **无** | — |
| 运行模式 | 11（出厂 3 = 位置）| 33（出厂 0 = 位置；另有 1 恒速 / 2 恒流 / 3 助力 / 5 位置+电流环）| 异 |
| **目标位置** | **116**（i32）| **42**（i16，BIT15 方向位）| 异 |
| **当前位置** | **132**（i32，±256 圈）| **56**（i16，多圈 ±7.5 圈）| 异 |
| 速度 | 128（i32，0.229 rev/min）| 58（u16，0.087°/step）| 异 |
| 电流 | 126（i16，mA）| 69（u16，**6.5 mA**/单位）| 异 |
| 电压 / 温度 | 144 / 146 | 62 / 63 | 异 |
| **P / I / D 增益** | 84 / 82 / 80（u16，**RAM**，0–16383）| **21 / 23 / 22**（u8，**EEPROM 区**，0–254）| 异 |
| 扭矩开关 | 64（0 关 / 1 开）| 40（0 关 / 1 开）| 异 |
| 硬件错误 | 70（+ `Shutdown(63)` 掩码）| 65（+ `卸载条件(19)` 掩码）| 异 |
| 过压 / 欠压限 | `32` 高限（出厂 **70 = 7.0 V**，只能调低）/ `34`（35 = 3.5 V）| `14`（出厂 **140 = 14.0 V**）/ `15`（出厂 **60 = 6.0 V**）| 异 |
| 温度上限 | 31（出厂 70 °C）| 13（出厂 70 °C）| 异（值同址不同）|
| 写入锁 | **无**（EEPROM 写入不需解锁）| 55（0 = 关锁→掉电保存 / 1 = 开锁→不保存）| 异 |
| **分辨率** | **4096 step/圈 · 0.0879°** | **4096 step/圈 · 0.08789°** | **同** |

**唯一真正「一样」的是分辨率与中位口径**（`rad = 2π·raw/4096 − π`，[[feetech-scs-bus]] §3 已记）。
其余每一项都要换算，**且「同址不同义」比「不同址」更危险** —— 例如两者都在 **44** 有寄存器：
XL330/飞特是 `Velocity Limit` / `PWM 开环速度`，MD 文档自称 `目标力矩`，而它自己的协议示例又把 44 当 `时间` 用。

## 4. 与飞特 SCS/STS/SMS 同族（证据）

| 证据 | 说明 |
|------|------|
| 地址表 | 5 · 6 · 8 · 9/11 · 13 · 14/15 · 19 · 20 · 21/22/23 · 33 · 40 · 42 · 46 · 55 · 56 · 58 · 62/63 · 65 · 69 **逐地址同构**（差在 7 · 16 · 25 · 30 · 34–36 · 44 等处的功能/单位/默认值）|
| 官方模板 | `01` 第 2 sheet 与飞特官方《磁编码 SMS&STS&HTS 十六进制指令生成表》**同一模板**，逐格同值（加速度 50/0–255/8.878°/s²、多圈「正负 7.5 圈」、读位置首址 56、圈数清除指令 10 …）|

（细节与原文摘抄见 [[vkesmd-md-series-docs-2026-09-21]]。）

## 5. 公平清单：同 · 异 · 未知

| | 项 |
|---|---|
| **同** | 分辨率 4096 / 0.0879° · 半双工 TTL 8N1 · 出厂 ID 1 · 出厂/`robotd` 目标波特率 1 Mbps · 多圈与磁编码思路 · 温度上限值 70 °C |
| **异（已证）** | 帧格式（2.0 vs 1.0 血统）· 全部运动核心地址 · 增益位置/位宽/存储区 · 模式语义 · 电压窗口与默认门限 · 无 `Model Number` · 无 `Protocol Type` |
| **未知（资料没给）** | **具体型号** · 尺寸 / 重量 / 花键 / 副输出轴 · 减速比 · 堵转扭矩 / 转速 / Kt · 额定电压（文档缺省窗口 6.0–14.0 V，模板测试电压 **12 V**）· 齿轮虚位 / 回差 · 工作模式是否真有「位置+电流环」|

**「未知」这一栏是本页最该被补的**：现在能判的只有「协议与寄存器不是 XL330」，
**判不了**「它作为执行器好不好、能不能上整机」。

## 6. 对本项目的后果

| 后果 | 依据 |
|------|------|
| **`robotd` / rustypot 通不了** | 它们按 DXL 2.0 帧 + 固定地址表；MD 两样都不同 → 要么换协议后端（[[feetech-scs-bus]] §6 · 约 500 行 + 库），要么出局 |
| **`dxl_ping.py` 读不到东西** | 帧头 / 校验不符即静默；且**没有 `Model Number(0)`** → [[xl330-vs-kpower-rd05t]] §3.1 那条「读回 1200 即自称 XL330」的守卫**必然失败** |
| **BAM 辨识闸门关** | 辨识链路要写 DXL `Position P Gain(84)`（[[bam-identification-bench]]）；MD 的 P 在 **21**、u8、**在 EEPROM 区**（要靠 55 锁才不磨损，见 [[feetech-scs-bus]] §4）→ 不是改个地址的事 |
| **机身 IMU 出局** | 官方 `imu_to_dxl` 板是 **DXL 从机（ID 200）**；总线协议一换就断（[[feetech-scs-bus]] §6 第 2 条）|
| **母线 6.0 V 要重新问** | 文档出厂电压窗口 **6.0 – 14.0 V**（模板测试电压 12 V）。**若实物是 12 V 档，6.0 V 母线上根本不该用** → 必须拿到规格书 |
| **保护语义不能类比** | MD 出厂 `卸载条件(19) = 44` → **电压保护是关的**；XL330 出厂 `Shutdown(63) = 53` **含** Input Voltage。两侧默认值方向相反，别照抄 |
| 出厂 ID / 波特率**表面一致** | MD 出厂 ID 1 @ 1 Mbps；XL330 被 `robotd` 也写成 ID 1..15 @ 1 Mbps（`baud=3`）→ **时间层能对上，协议层对不上** |

## 7. 判定路径

**先做便宜的、能出结论的 —— 两步，都不需要买回来。**

| # | 动作 | 通过判据 |
|---|------|----------|
| 1 | **向厂商问三件事** | ① **具体型号 + 规格书**（尺寸/重量/额定电压/堵转/减速比/花键）；② **是否存在 DXL 2.0 固件或型号**（若否 → 本路线直接出局，除非接受换协议）；③ **地址 44 是「目标力矩」还是「时间」**（文档自相矛盾处）|
| 2 | **上进 DXL 总线看应答**（有实物的几分钟）| `python3 scripts/dxl_ping.py scan --port … --baud 1000000,57600` 对 MD **只会静默** —— 但**静默只能证明「它不是 DXL 2.0」，不能证明「它是坏的」**。要判它自己好坏，得用厂商的 `VKESMD Debug`（1 Mbps）|

**第 2 步的读法很关键**：这台如果静默，**与 [[xl330-cn-bench-kit]] 那个「1 Mbps 全静默、57 600 才回」的坑不同** ——
那次是出厂波特率没对上，**这次是协议不同**，别混为一谈。
