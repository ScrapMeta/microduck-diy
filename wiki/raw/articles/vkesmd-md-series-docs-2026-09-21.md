## 1. 帧格式（`02` §2.1）

```
指令包  FF FF │ ID │ LEN=N+2 │ INSTR │ PARAM(N B) │ CHECKSUM
应答包  FF FF │ ID │ LEN=N+2 │ 设备状态 │ PARAM(N B) │ CHECKSUM
CHECKSUM = ~(ID + LEN + INSTR + ΣPARAM) & 0xFF   （和超 255 取低字节，再取反）
```

- 异步串行、8N1；ID **0–253**，**254 = 广播**（广播除 PING 外不应答；多舵机时禁用广播 PING）
- 双字节参数**低字节在前**（`02` §2.1.1 原文：字节顺序参考内存表，不同型号可能不同）

## 2. 指令表（`02` §2.2）

| 值 | 指令 | 参数长度 |
|----|------|----------|
| 0x01 | PING（查询工作状态）| 0 |
| 0x02 | READ DATA（读控制表）| 2（起始地址 + 字节数）|
| 0x03 | WRITE DATA | ≥1 |
| 0x04 | REGWRITE（异步写，等 ACTION 才动作）| ≥2 |
| 0x05 | ACTION（触发异步写）| 0 |
| 0x06 | RESET（**「把控制表复位为出厂值」**）| 0 |
| 0x82 | SYNCREAD（同步读多台）| ≥3 |
| 0x83 | SYNCWRITE（同步写多台）| ≥2 |

`01` 的十六进制指令生成表另有 **0x0A = 圈数清除**；`02` 的指令表未列它。

## 4. 上位机（`03` 手册）

- 串口 + 波特率（默认 **1 000 000**）+ 校验 NONE + 超时 25；搜索范围 **ID 0–253**，列表显示 **ID 与「型号」**
- EEPROM 掉电保存三步：**锁（55）写 0 → 改参数 → 锁写 1**；「写锁关闭期间，所有 EEPROM 修改都存 flash」
- 有自动测试（方波/正弦/扫频）+ 实时曲线（位置/速度/力矩，每格 1000 ms）、**固件升级**（可全总线批量，升级后除 ID 外的参数恢复出厂）

## 5. 文档内部矛盾（对照时先看这一节）

| # | 矛盾 | 出处 |
|---|------|------|
| 1 | **地址 44 是「目标力矩」还是「时间」**：内存表写 *目标力矩（6.5 mA）*；协议示例写 *位置 0x0800 + **时间** 0x0000 + 速度 0x03E8* 从 0x2A 起 6 字节；十六进制生成表把第 3、4 字节标注 *Time low/high* | `01` vs `02` §2.2.3、`01` 生成表 |
| 2 | **运行速度（46）范围**：内存表 **0–254**；协议示例却写 **1000**（0x03E8）| `01` vs `02` §2.2.3 |
| 3 | **过流阈值（28）范围**：内存表 **0–511**，说明却写「最大可设 500 × 6.5 mA = 3250 mA」（511 应 = 3.32 A）| `01` / `03` |
| 4 | **卸载条件（19）位表与出厂值不自洽**：正文只列 BIT0–3，出厂值 **44** 含 BIT5 | `01` / `03` |
| 5 | **相位（18）位定义只列 3 位**（BIT3/4/7），出厂值却是 **1**（未定义的 BIT0）| `03` vs `01` |
| 6 | 十六进制生成表的「速度」范围 **0–1023**，协议示例用 **1000**、内存表又是 **0–254** | `01` 三处 |

> 六条指向同一件事：**这批文档是「同一模板套多型号 / 多固件代」改写来的**，逐型号核对不能只靠它。
> 与 [[feetech-scs-bus]] §6 记的「同一寄存器在不同固件上语义漂移」是同一类风险，且这次**文档内部就漂了**。

## 6. 一处巧合（勿当线索）

`02` §2.2.7「同步读」示例的 ID1 回包末字节**恰好是 `0x55`**：
`FF FF 01 0A 00 00 08 00 00 00 00 79 1E 55` —— 那是 `~(01+0A+00+…)=0x55` 的**校验和**。
与本项目 XL330-CN 那个「回包多一固定字节 `0x55`」的**来源无关**（[[xl330-cn-bench-kit]] §「两个已经踩过的坑」），
不要因为都是 `0x55` 就把它当解释。
